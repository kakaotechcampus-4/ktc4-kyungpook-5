# 계획 대화 완료 후 깜빡임·흔들림

2026-11-05. 기준 `c82d319`에서 실제 `/planning`과 채팅 컴포넌트를 실행하고, API와 지연 SSE 응답만 고정해 재현했다. 실제 모델·서버 저장 검증과는 구분한다. 스크린샷은 생성하지 않았다.

## 확인한 원인

- 새 계획의 요청 ID가 생겨도 URL에는 아직 ID가 없어, 자기 요청을 ‘다른 계획’으로 안내했다. 완료 시 이 안내가 사라지고 ‘저장된 초안 없음’ 문구가 생겨 채팅 위치가 41px 오갔다.
- 첫 저장으로 `Conversation`의 React key가 바뀌어 입력창과 답변 DOM을 다시 만들었다. 이후 대화에서도 임시 답변과 저장된 답변은 별도 DOM이었다.
- 작업 내역은 저장 400ms 뒤 자동으로 접혔다. 측정한 2줄 사례에서 답변 높이와 스크롤이 22px 줄었다.
- 전송 버튼의 대기 문구·스피너로 입력창 폭이 60px 줄었다가 복원됐다.
- 320px에서는 ‘저장된 대화’로 바뀐 헤더가 한 줄 줄어, 채팅 영역이 26px 움직였다.

## 수정

- 첫 ID는 같은 대화 세션에서 채택한다. URL 반영 전에도 준비된 저장 캐시를 읽고, 명시적으로 새 계획·다른 계획을 선택할 때는 대화를 초기화한다. 최초 ID 반영은 history replace다.
- 임시·저장 메시지를 같은 추가 전용 타임라인으로 그린다. 한 계획 내 같은 위치·역할의 메시지는 DOM과 작업 내역 상태를 유지한다. 수신 중 사용자 메시지만 먼저 조회되면 임시 턴을 유지한다.
- 작업 내역은 자동으로 접지 않는다. 수신 중과 저장 후 같은 접기 버튼을 제공한다. 사용자가 과거 대화를 읽으면 자동 스크롤하지 않으며, 맨 아래에서는 내용 크기 변화에 맞춰 끝을 따른다.
- 조건 패널과 중복되는 초안 없음 문구는 제거했다. (처음에는 전송 중인 자기 요청을 '다른 계획'으로 안내하지 않게 고쳤으나, develop의 #342가 요청 기록을 행사별로 나누며 이 안내 자체를 없애서 병합 때 그 수정은 뺐다.)
- 전송 버튼 크기와 헤더 보조 문구 폭을 고정하고, 채팅 스크롤바가 생길 공간도 미리 확보한다.

## 검증

Chromium의 1440×900, 390×900, 320×900 CSS viewport에서 확인했다. 실제 기기 검증은 아니다. 최종 자동 회귀는 1440×900과 320×900에서 수행했다.

| 측정 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 첫 응답 전환의 채팅 위치 변화, 1440px | 41px | 0px |
| 각 응답 완료 후 자동 접기에 따른 높이·스크롤 변화 | 22px | 0px |
| 전송 중·완료 시 입력창 폭 변화 | 60px | 0px |
| 320px 헤더 줄바꿈으로 생긴 추가 위치 변화 | 26px | 0px |
| 첫 응답의 채팅 패널·입력창 DOM | 교체 | 유지 |
| 수신 중 답변 → 저장된 답변 DOM | 교체 | 유지 |

첫 대화+후속 2회 각각의 프레임별 위치·크기·스크롤·포커스를 검사했다. 추가로 이전 대화를 읽는 중 전송, 수동 접기·키보드 펼치기, 명시적 실패 후 입력 복원, 새 계획 초기화·이전 계획 재선택, 다른 계획에 확인할 요청이 남아 있어도 이 계획을 잠그지 않음(#342 병합 후)을 검사했다. 빌드·변경 파일 ESLint·계획 관련 Node 테스트 55개도 통과했다.

회귀 스크립트는 Playwright가 설치된 환경에서 실행한다. 필요하면 `PLAYWRIGHT_MODULE`에 모듈 경로, `PLAYWRIGHT_CHROMIUM_EXECUTABLE`에 Chromium 실행 파일 경로를 지정한다. 기본 브라우저는 Playwright의 Chromium이다.

```sh
# fe 디렉터리. 다른 터미널에서 Vite를 먼저 실행한다.
npm run dev -- --host 127.0.0.1 --port 5182 --strictPort
node scripts/verify-planning-chat-stability.mjs 1440
node scripts/verify-planning-chat-stability.mjs 320
```

`PLANNING_BASE_URL`로 로컬 서버 주소를 바꿀 수 있다. `PLANNING_TRACE_OUTPUT`을 지정하면 프레임별 JSON을 그 경로에 저장한다. 스크립트의 모든 API와 SSE는 합성 데이터로 대체하며 계정 생성·모델 실행·실제 저장 요청은 하지 않는다.
