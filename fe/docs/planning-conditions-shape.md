## 확정한 목적과 구성

- PC에서 행사 준비를 반복하는 동아리 운영진이 토리가 이해한 조건을 검증한다. Operate 모드이며 생성 시점 판단보다 조건 해석 확인에 우선순위를 둔다.
- P1은 대화·조건 확인·생성에 집중한다. 오른쪽 첫 카드 ‘이번 행사 조건’은 여섯 조건, 잠정 근거, 생성 안내·버튼 순서다. 기존 색·토리·공용 컴포넌트·조건 변경 강조를 유지한다.
- 기존 초안의 단계 목록·AI 검토·행사 시작은 P2에서 제공한다. P1에는 ‘기존 초안 검토하기’ 진입만 남긴다. 기존 초안 데이터와 P2 기능을 삭제하는 변경이 아니다.
- 참고 기록은 통합 카드 다음에 위치한다. 조회 전 자리·최신 결과·더 보기·이전 조회·출처·원본 다운로드를 유지한다. 펼쳐도 생성 버튼을 아래로 밀지 않는다.
- 생성 이후는 #338의 요청 잠금·공통 생성 화면·저장 확인·실패 복구·P2 이동을 재사용한다. 새로운 생성 로직이나 시안의 임의 완료 타이머를 제품에 넣지 않는다.

## 상태와 정보

값과 상태를 함께 읽을 수 있게 한다. 확정·잠정·미정·나중에를 유지하며, 값이 없는 미응답을 명시적 미정으로 단정하지 않는다. 무료는 참가비 0원이다. 잠정 근거는 실제 evidenceQuote가 있는 경우에만 표시한다. 긴 행사 이름·장소·인용문은 확인 가능한 형태로 줄바꿈한다.

생성 가능 여부는 서버 generationReadiness만 사용한다. FE가 입력 완료 개수·종류만으로 생성 가능 정책을 만들지 않는다. 일반 대화/검색 대기는 버튼을 잠그되 생성 중이라고 부르지 않는다. 생성 불가·판정 조회 불가·실제 생성 시작·생성 실패는 서로 다른 상태다. 기존 초안이 있어도 현재 조건과 초안의 불일치를 FE가 추측하지 않는다.

기본 버튼은 ‘이 조건으로 초안 만들기’, 기존 초안이 있으면 ‘이 조건으로 다시 만들기’다. 후자는 기존 단계가 새 초안으로 교체되는 의미를 설명한다. 교체 동의·서버 보호 계약의 신규 구현은 #316/#220 등 기존 연계 범위에 남긴다.

## 구현

- LivePlanning의 생성 안내·버튼을 PlanFacts 하단으로 옮겼다. P1의 단계 요약·목록·검토·시작과 중복 상단 P2 링크는 제거했고, 같은 카드의 ‘기존 초안 검토하기’로 P2를 연다. PlanStageNav와 제목은 재사용한다. P2의 검토·시작 구현은 그대로다.
- PlanFacts는 조건 목록과 호출부가 전달한 생성 영역을 같은 카드에 표시한다. localReadiness와 이전 분리 생성 카드 API를 제거해 생성 가능 정책을 계산하지 않는다. demo 경로도 같은 구조를 사용하지만 예시 조건임을 알린다.
- 조건을 dl/dt/dd로 읽을 수 있게 하고 카드 제목과 생성 버튼의 설명을 연결했다. 체크/잠정 표시는 장식 SVG이고 확정 상태는 낭독용 글자를 제공한다. 긴 값·근거는 말줄임 없이 줄바꿈하며 기존 변경 강조와 모션 감소 처리를 유지한다.
- 버튼의 disabled/loading/handler, #338 generationFlow 분기와 실패/복구 처리를 유지했다. 생성 버튼 이름에 맞춰 기존 E2E를 갱신했다. 새로운 생성 요청·상태 머신·재생성 보호 우회는 추가하지 않았다.

### 확인된 서버 계약 한계

제품 PlanDraftOut은 conditions·conditionMeta·deferredTopics를 반환한다. 값이 있는 조건의 잠정/명시 메타와 근거는 보존하지만, **null에 대해 ‘아직 미정이라고 답함’과 ‘나중에 정하자고 답함’을 구분하는 별도 사유·근거 필드는 없다.** 현재 AI 계약과 공개 readiness는 두 표현을 같은 보류 주제로 취급한다.

따라서 기존 toFacts의 실제 데이터 매핑을 유지했다. 값이 없는 미응답은 ‘아직이에요’, 서버 보류 주제는 ‘나중에 정해요 · 나중에’로 구별하며, 참가비 0원은 ‘무료’다. PlanFacts에 명시적 status=미정이 전달되면 ‘미정’으로 표시할 수 있지만 **현재 제품 API에서 두 발화의 독립 표기가 구현됐다고 주장하지 않는다.** 이를 별도로 보여주려면 서버가 의미를 보존해 전달하는 후속 계약이 필요하다. FE가 대화 문자열에서 추정하거나 생성을 허용하는 정책을 추가하지 않았다.

## 검토용 시안

합성 데이터로 새 계획·생성 가능·추가 답변 필요·대화/검색 대기·기존 초안 상태를 비교한다. 인원 변경 예시와 조건 강조, 기록 펼치기·이전 조회, 기존 P2 및 생성 화면으로의 연결 의도를 확인한다. 실제 AI·HTTP·DB·발송에 연결하지 않으며 제품 검증 완료를 뜻하지 않는다.

## 완료 기준

조건 확인 → 대화로 정정 → 변경된 조건 확인 → 같은 카드에서 생성 결정이 가능해야 한다. 기록을 펼쳐도 CTA 위치가 유지돼야 한다. 제품 구현 시 맥북 14인치의 실제 CSS viewport와 1280×800·1024px 경계·390px·큰 화면, 키보드·모션 감소를 확인하고 전후 증거를 남긴다.

시안 검토 당시에는 제품 코드를 수정하지 않았다. 이후 사용자가 시안을 채택하고 실제 구현을 요청해 위 FE 범위를 별도 worktree에서 구현했다. 원래 작업 공간의 미커밋 변경은 보존했다.

재현은 fe/에서 아래처럼 실행한다. 세션 파일은 검증 전용 합성 계정의 token·clubId를 담으며 저장소 밖에 둔다. 실제 모델 실행은 기존 `generation.mjs`의 별도 옵션을 사용한다.

```sh
npm run build
npm run lint
node --test tests/*.test.mjs
CONDITIONS_TEST_SESSION=/path/to/synthetic-session.json CONDITIONS_UI_ORIGIN=http://127.0.0.1:5177 node tests/e2e/conditions.mjs
GENERATION_TEST_SESSION=/path/to/synthetic-session.json GENERATION_UI_ORIGIN=http://127.0.0.1:5177 node tests/e2e/generation.mjs
```

이번 검증은 5177의 FE에서 `/api`를 검증 전용 8005 API로 프록시했다(로컬 임시 Vite 설정, 저장소 설정 변경 없음). 재현 시 같은 API 연결을 준비한다. 브라우저 런타임은 `PLAYWRIGHT_MODULE`/`P2_BROWSER_PATH`, UI/API 주소는 `CONDITIONS_UI_ORIGIN`/`CONDITIONS_API_ORIGIN` 또는 기존 `GENERATION_*` 옵션으로 지정한다. 비교 캡처를 원하면 변경 전 FE의 별도 주소를 `CONDITIONS_BASELINE_ORIGIN`으로 지정한다. 인증 세션·토큰·환경 파일은 변경 목록에 포함하지 않는다.
