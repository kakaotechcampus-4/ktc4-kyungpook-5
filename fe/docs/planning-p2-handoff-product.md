# 운영해

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

주 사용자는 PC에서 비슷한 행사를 반복해서 준비하는 동아리 운영진이다. 사용자 확인: 2026-11-05.

## Product Purpose

토리와 대화하며 행사 조건을 정하고, 생성된 행사 단계와 일정을 확인·수정한 뒤 운영을 시작한다. 사용자가 전체 계획 과정을 자연스럽게 이해하도록 돕는다.

## Operating Context

행사 조건을 정하는 P1은 대화 중심, 생성된 단계 흐름을 검토·수정하는 P2는 계획 중심으로 구성하는 방향에 합의했다. P2에서는 이전 대화를 읽기 전용으로 열어볼 수 있고 새 대화는 P1에서만 한다. P1의 조건 요약과 생성 버튼은 한 덩어리로 묶는다. 채팅에서 생성 요청을 수락하거나 별도의 버튼을 눌러 초안을 생성할 수 있다. 세부 전환·상태 정책과 화면 명칭은 설계 검토 중이다.

## Capabilities and Constraints

- 초안 생성과 운영 시작을 구분한다.
- ‘행사 시작’은 행사를 진행 상태로 전환한다. 실행·발송에는 별도 승인이 필요하다. 사용자 확인: 2026-11-05.
- 저장소에는 대화에서 정한 조건, 생성 가능 여부, 생성된 단계, 참고한 과거 기록과 출처를 표시하는 구현이 있다. 로컬 구현이 운영 배포 상태와 같다고 가정하지 않는다.
- 이번 요청은 현재 구현과 첨부 디자인을 바탕으로 UI/UX 방향을 논의하는 작업이다. 코드 수정과 구현은 요청 범위에 포함하지 않는다.
- 첨부한 현행 화면은 4K 모니터 환경이며 맥북 프로 14인치에서는 화면이 충분히 차 보인다. 화면 밀도는 실제 브라우저 표시 크기에서 판단한다.
- 계획 중인 초안을 다시 계획에서 열면 P2로 진입하고, 조건을 바꿔도 기존 초안을 유지하는 방향에 동의했다. 행사 목록에도 계획 중 행사가 있어 같은 행사의 진입 동선을 함께 고려한다.
- P2 설계·구현을 먼저 진행하며, 생성 중 대화 복귀는 이후 편의 기능으로 추가한다. 현재는 코드 구현 없이 설계를 정리하는 단계다.
- P2 기본 시안과 두 수정 동선은 사용자 채택을 마쳤다. 채택한 표면과 구현 범위는 fe/docs/planning-flow-ux-shape.md §17 및 #325에서 관리한다. 제품 구현은 아직 시작하지 않았다.

## Brand Commitments

서비스 이름은 운영해, 대화 상대는 토리다. 친근하면서도 세련된 서비스 UI를 지향한다.

## Open Decisions

행사 목록/상세에서 계획으로 여는 위치, 생성 중 새로고침 복원과 두 생성 경로의 교체 동의 계약은 후속 설계/연동에서 확인한다. P2 시안 채택을 전체 후속 정책 확정이나 제품 구현 착수로 해석하지 않는다. UX 설계는 fe/docs/planning-flow-ux-shape.md, 상위 작업은 #317이며 구현 단위를 나누어 등록했다.
