# 기록 색인·검색 평가 기록

청킹·임베딩·검색 규칙을 바꿀 때 같은 조건으로 다시 재고, 이전 값과 비교하기 위한 기록이다.
최근 기록을 위에 쌓는다. 값은 예시 기록(`tests/fixtures/records/`) 기준이다.

## 재는 방법

```bash
cd be && uv run python app/ai/scripts/check_index_record.py [--json 결과.json] [--no-header]
```

- 키가 필요해 CI에서 돌리지 않는다. `be/.env`의 `AI_EMBEDDING_*`를 쓴다.
- 색인: 예시 기록 4종과 실제 한컴 PDF(`be/tests/fixtures/records/sample_report.pdf`, BE 파서 경유)
- 검색: 예시 기록 4종을 메모리 port에 넣고 질문 6개로 상위 3개를 본다. 1개는 기대값 없이 관찰만 한다
- 지표: 기대 청크가 1위인 질문 수(hit@1), 3위 안에 든 질문 수(hit@3)
- `--no-header`: 청크 임베딩에서 문서명·위치 이름표를 빼고 잰다(이름표 효과 비교용)

질문 6개는 스크립트의 `QUESTIONS`에 있다. 질문을 바꾸면 이전 기록과 직접 비교할 수 없으므로 기록에 적는다.

### 관찰

- **이름표는 맞는 문서를 끌어오지만 문서 안 구분은 흐리게 한다.**
  "작년 봄 MT 예산 초과"에서 이름표가 있으면 상위 2개가 2025 봄 MT 결과보고였고, 없으면 2024 장부가 1위였다.
  반면 같은 문서의 청크끼리 같은 이름표를 공유해 서로 비슷해지고, 점수가 전반적으로 낮아졌다.
  "지출 승인"은 이름표가 있을 때만 장부가 회칙 제12조를 앞섰다(0.374 vs 0.365).
  질문 5개라 결론을 내기에는 적다. 이름표 형식(위치 빼기, 파일명만 등)은 #72 평가 세트로 다시 본다.
- **"초과 42,000원"이 적힌 정산 청크가 두 경우 모두 3위 안에 없었다.** 질문의 "예산"이 `2. 예산` 제목과 겹쳐
  예산 표가 1위였다. 예산 표에도 답(합계 1,260,000 → 1,302,000)이 있지만 계산이 필요하다.
  검색어 정리(#72)와 키워드 검색 결합(D-04)의 확인 대상이다.
- **숫자 표기 차이**: 질문은 "30만 원", 회칙은 "300,000원"이다. 금액이 많은 장부 청크가 회칙과 비슷한 점수를 받았다.
- **연도 구분**: "MT 숙소 비용"에서 2025 봄과 2024 가을 장부의 점수 차가 0.003~0.03이었다.
  "작년" 같은 시기 해석은 검색어 정리(#72)가 맡는다.
