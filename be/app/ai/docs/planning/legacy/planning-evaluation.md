### 관찰된 대화 흐름

- 인원 축소 요청 → 40명 확정 → 일정 보류: pending 해결과 다음 질문이 기대대로 이어졌다.
- 인원 수정 질문 도중 과거 장소 조회 → 인원 40명 답변: 과거 조회가 올해 인원 조건을 바꾸지 않았고 기존 수정 메모도 보존됐다.
- 시작일만 뒤로 옮겨 날짜 역전 → 날짜 쌍을 올바르게 지정: 원본 유지·충돌 메모·후속 해결을 확인했다.
- 수정+조회 혼합: 인원 40명과 과거 장소 참고를 함께 반환했고 불필요한 기본 질문은 생략했다.
- 대상 불명 조회: 조회 질문은 맞았지만 아래와 같이 미해결 수정이 잘못 추가됐다.

### 불일치 1건: 조회 모호함과 조건 수정 모호함의 혼동

입력은 “그때 그 행사 비용은 얼마였어?”이며 수정 요청이 아니다. 조회 판단은 CLARIFY와 “어느 MT 행사의 비용을 조회할까요?”를 반환했다. 하지만 추출 모델은 동시에 `budget_total / AMBIGUOUS_REFERENCE`를 unresolved에 반환했다. 조립 코드는 그 결과를 pending으로 보존하고 ready_to_generate=false로 계산했다. 기대값은 pending 없음·ready=true다. 올해 조건값 자체는 바뀌지 않았다.

이 사례에서 확인한 원인은 추출 출력에 조회 모호함이 조건 수정 모호함으로 들어온 것이다. 조건 추출과 조회 판단을 독립 모델 호출로 수행하는 경계의 문제이며, 코드가 인용 존재만 검사해서는 의미 오분류를 막지 못한다. 이번 실행 뒤 프롬프트·기대값·기능 정책을 바꾸지는 않았다. 후속에는 조회만 요청한 발화와 혼합 요청을 구분하는 라벨을 늘리고, 추출 정책 보완 또는 두 판단 간 의미 검증을 한 요소씩 비교해야 한다. 조회가 포함됐다고 모든 unresolved를 삭제하면 혼합 요청의 실제 모호한 수정을 잃으므로 그런 처리는 하지 않는다.

### 한계와 재실행

9/10은 초기 합성 세트의 복합 체크이며 일반 정확도나 승인 성능이 아니다. 질문 문구는 정확한 문자열 대신 대상 필드만 비교했고, 답변 의미·조회 사실의 정확도는 별도 자동 점수로 측정하지 않았다. 출처 체크는 실제 조회 2턴에서 검색된 청크의 출처를 썼는지만 확인하며 나머지 턴에는 출처가 없어 자명하게 통과한다. 권한·설정·모델 실패 처리의 라이브 장애 실험도 하지 않았으며 기존 단위 테스트로 구분한다. 메모리 저장소를 사용하므로 실제 BE DB·FE·공개 API는 미검증이다.

```sh
# be/에서 실행. 실제 API 사용. 불일치가 있으면 종료 코드 1.
.venv/bin/python -m app.ai.scripts.eval_planning_turns --json app/ai/docs/planning/legacy/evaluation-results/planning-turns-새실행일.json
```

평가 스크립트 import는 환경변수를 변경하지 않고 실제 실행의 AISettings만 .env를 읽는다. 키·내부 주소·예외 원문은 결과에 저장하지 않는다. 핵심 코드에 입력·분기·상태 보존 이유의 주석을 추가했고 AI 전체 566개 테스트가 통과했다. 평가셋 확대·실패 유형별 분석·검색 품질 개선은 별도 후속 과제로 유지한다.

[사례별 결과 JSON](evaluation-results/planning-conditions-2026-10-22.json)에 실제 후보·적용 operation·미해결 근거·지연·fixture 및 핵심 코드 SHA-256을 남겼다. 커밋만으로 미커밋 구현을 재현할 수 없으므로 해시도 함께 기록했다. BE 저장·FE 표시 시간을 포함하지 않으며, 샘플이 18개라 nearest-rank p95는 최댓값과 같다.

관찰: 모호한 인원 변경은 기존 값 보존+NEEDS_CLARIFICATION, 날짜 역전은 코드에서 VALIDATION_FAILED와 원본 보존, 짧은 수락은 pending_offer 및 앞선 발화 근거에 연결됐다. 인용된 지시문 사례는 조건을 바꾸지 않았다. 전자는 모델과 코드가 결합한 최종 결과이며 모델의 원시 operation 정확도를 별도 측정한 점수는 아니다.

한계: 정답은 AI 작성 후 사람 검수 전이고, 작은 합성 세트를 한 번 실행했다. 이 18/18을 일반적인 정확도 100%, 안정적 p95 또는 주입 공격 방어 보장으로 해석하지 않는다. 반복 실행·실제 사용자 발화·필드별 오류율 평가는 남아 있다.

### 연결 과정에서 확인한 문제와 수정

1. 제한된 네트워크 환경에서는 18건 모두 AIRetryableError로 끝났다. 모델 품질 결과에서 제외하고 권한을 높여 연결을 재확인했다.
2. 실제 게이트웨이가 첫 요청에 HTTP 400 `invalid_json_schema`를 반환했다. Pydantic discriminated union이 생성한 `oneOf`를 허용하지 않는다는 응답이었다. 모델 추출 이전의 스키마 거부다.
3. field/op의 Literal과 엄격한 값 타입을 유지하면서 일반 Union으로 변경했다. JSON Schema는 `anyOf`를 사용한다. 프롬프트·평가 입력은 바꾸지 않았다. 자유 JSON이나 타입 검사 제거로 우회하지 않았다.
4. 수정 후 18개 요청이 모두 처리됐고 결과가 일치했다. oneOf/discriminator 재유입을 막는 회귀 테스트를 추가했다. 로컬 스키마 검증만으로 공급자 호환성을 보장할 수 없다는 점이 확인됐다.

관련 이슈의 원격 업데이트는 이번 작업에서 수행하지 않았다. 구현 PR/Issue 정리 시 이 문제·원인·결과를 함께 옮긴다.

`tests/test_planning_extraction.py`는 변경 적용의 원자성, 원본 보존, 이번 발화/문맥 근거, 단일 제안 수락, 중복·상충 변경, 잘못된 스키마와 모델 실패 전파를 검증한다. 스냅샷 형식 검증은 `test_planning_conditions.py`에 있다.

| 다음 달쯤 → 일정은 나중에 정할게 | 일정 확인 질문 → 시작/종료 보류 후 인원 질문 |

예상 질문 필드가 6/6턴 일치했다. [실제 추출·질문·상태 기록](evaluation-results/planning-questions-2026-10-22.json)을 보존했다. “아직 모르겠어”의 DEFERRED 해석은 모델이 담당하고 질문 반복 억제는 코드가 담당한다. 추출 오류가 나면 이 정책만으로 사용자의 의도를 복구할 수 없다.

통합 점검 후 부분 일정(시작 또는 종료만 존재)에는 미정 날짜만 묻는 문구를 보완했다. 이 분기는 추가 단위 테스트로 검증했고 해당 문구의 실제 모델 재호출은 하지 않았다. 결과 파일의 current_source_sha256은 이 보완 후 코드 기준임을 별도 표시했다.

질문 단위 테스트 13개 및 기존 AI 테스트를 포함해 총 472개가 통과했다. 행사 격리, 질문 우선순위, 명시적 재요청, 미루기, CLEAR 후 재질문, 값이 있는 항목 제외, 날짜 충돌/부분 일정 등을 확인한다. BE 상태 저장·브라우저 UI·장기 대화는 아직 검증하지 않았다. 여러 미해결 항목의 장기 보존/해결 관리는 작업 5/12에서 통합해야 한다.

재실행: be/에서 `uv run --frozen --group dev python -m app.ai.scripts.check_planning_questions`.

## 조건 추출 평가 재실행

`tests/fixtures/eval/planning_conditions.json`에 합성 사례 18개를 두었다. **AI가 작성한 초안이며 사람 검수 전**이다. 단위 변경, 명시적 해제, 무료, 부정·과거 인용·자기 정정, 다중 변경, 날짜 충돌·상대 날짜, 모호한 수락·명시적 제안 수락, 지시문 인용을 포함한다. 학습 데이터나 승인된 성능 기준으로 사용하지 않는다.

be/에서 설정한 뒤 실행한다:

```sh
uv run --frozen --group dev python -m app.ai.scripts.eval_planning_conditions
```

모델명·프롬프트 버전·커밋·미커밋 여부·샘플 수와 각 사례의 결과를 JSON으로 출력한다. 정확한 최종 조건/상태/미해결 필드 일치 수, 잘못된 필드와 지연을 확인한다. API 실패도 누락 없이 실패 사례로 남긴다. 승인 성능을 주장하기 전에 기대 정답을 사람이 검수하고, operation 수준의 누락·오탐/CLEAR 오류·모호함 확정 비율과 p50/p95를 포함하는 평가로 확장한다. 현재 작은 사례 집합은 초기 연결 확인용이다.

현재 스키마는 위 실제 호출에서 게이트웨이 수용을 확인했다. 공급자나 스키마를 바꿀 때도 로컬 검증과 실제 호환성 검증을 나누어 수행한다. 위 결과를 초기 기준값으로 남기고, 프롬프트/스키마 변경은 같은 사례로 비교한다.
