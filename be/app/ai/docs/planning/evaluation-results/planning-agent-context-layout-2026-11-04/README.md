| 변형 | 호출 | p50 | p95 | 평균 | 캐시가 걸린 호출 |

세션별 대화 호출 p50(v7 → v8)은 3.20 → 2.91, 3.37 → 2.88, 3.22 → 3.00으로 세 세션 모두 같은 방향이었다. 같은 세션·라운드·사례의 v7과 v8을 짝지은 90쌍에서 요청 1건의 대화 호출 시간 합은 중앙값 0.56초, 평균 1.21초 줄었고, 66쌍에서 v8이 빨랐다. 평균 차이가 중앙값보다 큰 것은 v7 쪽 느린 호출(최대 10초대) 몇 건의 영향이다.

p95는 C1과 C2에서 v8이 조금 더 길었다(5.86 → 6.20, 12.09 → 12.59). 꼬리 쪽 느린 호출은 이번 변경으로 줄었다고 말할 수 없다.

### G1 실패 차이

G1 통과는 v7 28/30, v8 24/30이었다. 실패 8건은 모두 생성 모델이 쓴 계획이 결정론적 검증(`validate_plan`)에서 거절된 `invalid_plan`이었다. 대화 모델이 고른 행동은 60건 모두 같았다(`generate_event_plan`, quote "응, 만들어줘.", 같은 권유 ID, `use_current_conditions=false`, 함께 쓴 글 없음). 생성 입력은 이 인자와 초안·이력의 글로만 만들어지므로 두 변형의 생성 입력은 같다. 그래서 이 차이는 실행 문맥 위치가 아니라 생성 호출의 결과 차이로 본다. #263에서도 같은 생성 경로인 G2가 30건 중 5건 `invalid_plan`이었다. 생성 시간 p50도 v7 20.32초, v8 19.15초로, 같은 코드인데 1초가량 차이가 났다. G1의 요청 p50 차이(2.5초)에는 이 생성 쪽 차이가 섞여 있으므로 대화 호출 효과로 읽지 않는다.

## 해석의 한계

- 같은 합성 MT 상황의 짧은 이력(4개)만 쟀다. 이력이 길어지면 캐시로 재사용되는 부분도 길어지지만, 그때의 시간 효과는 재지 않았다.
- 대화 호출 p50은 줄었지만 p95는 줄지 않았다. 사용자가 체감하는 가장 긴 대기가 줄었다고 말하지 않는다.
- 공급자의 캐시 규칙(시스템 메시지 전체 일치)은 이번 실험에서 관찰한 동작이다. 공급자 문서로 확인한 규칙이 아니며 바뀔 수 있다.
- 측정 시각이 새벽 2~3시대다. 다른 시각의 절대 시간과 비교하지 않는다.
