# 한 응답에 Tool 하나/여러 개 비교 — 2026-11-04

관련 [#265](https://github.com/kakaotechcampus-4/ktc4-kyungpook-5/issues/265)(상위 [#262](https://github.com/kakaotechcampus-4/ktc4-kyungpook-5/issues/262)), AI-PLAN-01.

토리 대화 모델이 한 번 답할 때 Tool을 하나만 고르게 한 설정(`single`, 지금까지)과 여러 개를 함께 고르게 한 설정(`multi`)을 같은 실행 안에서 번갈아 쟀다.

```text
"예상 참가 인원을 60명으로 바꿔줘. 계획 초안은 만들지 마." (C2)

single  호출 1 인원 변경 (2.7초) → 호출 2 생성 보류 (2.4초) → 호출 3 답변 (2.1초)   요청 p50 7.19초
multi   호출 1 인원 변경 + 생성 보류 (3.8초) → 호출 2 답변 (2.3초)                  요청 p50 6.17초
```

## 한 줄 결론

**multi는 C2에서 30건 모두 두 Tool을 한 응답에 담아 모델 호출이 3번에서 2번으로, 요청 p50이 약 1초 줄었다. 하지만 보류 재개가 섞인 발화에서 통과가 줄어(11/13 → 7/13) 측정 전에 정한 기준 ①을 채우지 못해 채택하지 않았다.** 코드의 값은 `PARALLEL_TOOL_CALLS = False`다.

## 채택 기준 (측정 전에 #265에 적음)

| 기준 | 결과 |
| --- | --- |
| ① C2 통과 수와 보류 경계 대조 사례 통과 수가 사례마다 single 이상 | C2 30/30 = 30/30. 대조 5종 중 4종은 3/3 = 3/3, `date_resume`만 single 3/3, multi 2/3 → **미충족** |
| ② 요청당 대화 모델 호출 수가 multi가 적음 | 3번 → 2번, 만족 |
| ③ C2 성공 p50이 세 세션 모두 multi가 짧음 | 7.02 / 7.27 / 7.30초 → 6.10 / 6.01 / 6.22초, 만족 |

①을 1건 차이로 채우지 못했고, 3번만으로는 우연인지 구분할 수 없어 사용자와 정한 대로 `date_resume`만 변형마다 10번씩 추가로 번갈아 쟀다. 추가 측정에서도 multi가 낮아(8/10 → 5/10) 채택하지 않았다. 처음 측정의 2/3도 그대로 둔다.

## C2 결과

시간은 초다. p50은 가운데 값, p95는 95% 위치의 선형 보간값이다(R7).

| 변형 | 통과 | 요청 p50 / p95 | 요청당 대화 호출 | 한 응답에 두 Tool |
| --- | --- | --- | --- | --- |
| single | 30/30 | 7.19 / 10.09 | 3번 (30건 모두) | 0/30 |
| multi | 30/30 | **6.17 / 7.49** | 2번 (30건 모두) | **30/30** |

- 같은 세션·라운드끼리 짝지은 30쌍 중 26쌍에서 multi가 빨랐고, 차이 중앙값은 1.09초였다.
- 생성 보류는 60건 모두 `deferred`였고, 보류의 기준 조건이 60명 초안과 같았다.

### 호출 하나가 빠졌는데 왜 1초만 줄었나

| 변형 | 호출 1 | 호출 2 | 호출 3 |
| --- | --- | --- | --- |
| single | 2.66초 (출력 110토큰) | 2.37초 (66토큰) | 2.11초 (31토큰) |
| multi | **3.77초 (출력 200토큰)** | 2.27초 (29토큰) | — |

multi의 첫 호출은 Tool 요청 두 개를 함께 쓰므로 출력이 약 2배였고 그만큼 길었다. 빠진 호출(약 2.4초)에서 늘어난 출력 시간(약 1.1초)을 뺀 만큼 줄었다.

## 보류 경계 대조 사례

| 사례 | single | multi |
| --- | --- | --- |
| 생성 보류 표현 변형 | 3/3 | 3/3 |
| 날짜 직접 보류 | 3/3 | 3/3 |
| 날짜와 장소 함께 보류 | 3/3 | 3/3 |
| 직전 날짜 질문에 "그건 나중에" | 3/3 | 3/3 |
| 기존 날짜 보류에서 "날짜는 다시 얘기하자" (`date_resume`) | 3/3 | 2/3 |
| ↳ 추가 측정 10번 | 8/10 | 5/10 |
| ↳ 합계 | **11/13** | **7/13** |

```text
상황: 날짜 이야기를 보류해 둔 상태
발화: "날짜는 다시 얘기하자. 인원은 60명으로 바꿔줘. 초안은 만들지 마."
기대: 인원 60명 반영 + 날짜 보류 풀기 + 생성 보류
실패: 인원 반영과 생성 보류는 했지만 날짜 보류를 그대로 둠 (두 변형의 실패 모양이 같음)
```

이 문장은 #205에서 "다시 얘기하자"가 재개인지 나중에 하자인지 모호해 남긴 실패이고, 같은 날 새벽 #269 측정에서는 v7·v8 모두 0/3이었다. 원래 결과가 흔들리는 사례다. 그래도 두 번 모두 multi가 낮았으므로 설정 영향이 아니라고 말할 수 없다.

원인은 확인하지 않았다. 이 발화는 할 일이 세 가지(날짜 재개, 인원 변경, 생성 보류)라서, 한 응답에 모두 적을 때 날짜 재개를 빠뜨리는 경우가 늘었을 수 있다(추측). 대조 사례 기록에는 Tool 인자가 없어 실패한 응답에 무엇이 빠졌는지는 보지 못했다. 원인 분석은 후속 작업이다.
