# 초안 작성 중 단계 신호: 기준 측정과 채택 측정 (#389, 2026-11-07)

#389는 생성 모델이 계획 JSON을 쓰는 동안 단계 하나의 `code`를 다 쓸 때마다 `generation_step`(위치·코드·고정 이름)을 보낸다. 화면은 「초안을 작성하는 중이에요」를 펼치면 그 이름을 차례로 쌓는다.

**기준 측정에서 진행 기준을 넘었고, 채택 측정에서 측정 전 기준 다섯 가지를 모두 만족해 채택했다.** 모델은 20건 모두 `steps`를 맨 앞에, 단계마다 `code`를 맨 앞에 썼다. 13단계 코드는 작성 구간(p50 약 7.3초)의 앞 약 65% 동안 p50 4.8초에 걸쳐 차례로 나왔다. 바꾼 뒤 전체 p50은 G2 −0.07초, G1 −0.50초로 늘지 않았다.

```text
「이 조건으로 초안 만들기」 (G2, 기준 측정 p50)

0초      generation_started                → 토리가 생각 중이에요
약 4.9초  첫 글자 조각 (generation_writing)  → 초안을 작성하는 중이에요
+0.06초   단계 0 code 끝 → 「담당 인원 배치」
          … 약 0.4초마다 한 단계 …
+4.8초    단계 12 code 끝 → 「피드백 기록」     ← 단계 이름이 쌓이는 구간
          (제외 단계·가정·질문 작성 + 검증, p50 2.6초)
generation_finished
```

## 측정 전에 정한 기준

[#389 코멘트](https://github.com/kakaotechcampus-4/ktc4-kyungpook-5/issues/389#issuecomment-6689456049)에서 측정 전에 정했다.

기준 측정(구현 전):
- 20건 모두 `steps`가 맨 앞이고 모든 단계에서 `code`가 맨 앞이다. 하나라도 아니면 앞에서부터 읽는 설계를 다시 본다
- 첫 단계 `code`가 끝난 때부터 마지막 단계 `code`가 끝난 때까지 p50 1초 이상이다

채택 측정(구현 뒤), 사례마다:
1. 전체 p50(새 − 기존)이 +0.5초 이내
2. 계획 검증 통과 수가 기존 경로보다 1건까지 적은 것은 허용, 2건 이상 적으면 미달
3. 새 경로에서 생성에 성공한 모든 요청의 단계 신호 코드 순서 = 최종 초안 `steps` 코드 순서, 단계마다 정확히 한 번
4. `excluded_steps`의 코드로 나간 신호가 없다
5. `generation_started → generation_writing → (단계 신호들) → generation_finished` 순서

2번에서 1건 감소를 허용한 이유: #388에서 받는 방식만 바꿨는데 G1 검증 통과가 10 → 9로 나왔고, 두 경로의 요청 본문이 같다는 것을 시험으로 고정해 모델 출력의 흔들림으로 판단했다. 이전 측정에도 같은 종류의 실패가 있었다(#239 18건 중 2건, #264 30건 중 2건). 이번 변경도 받은 글자를 읽기만 하고 요청은 바꾸지 않는다.

- 마지막 코드 뒤 p50 2.4~2.6초 동안은 이름이 더 붙지 않는다. 마지막 단계의 목적·행동, 제외 단계, 가정·질문을 쓰고 검증하는 시간이다. 화면은 이 동안 마지막 단계를 진행 중으로 둔다.

## 한계

- 고정 입력에서 모델이 20건 모두 13단계를 다 넣어 `excluded_steps`가 비었다. 제외 단계를 무시하는 동작은 실제 모델로는 확인하지 못했고, 단위 시험(`test_step_reader.py`, `test_planning_progress.py`)으로만 확인했다.
- 생성 모델 호출 안의 SDK 수신 시각이다. 제품 화면에서는 BE 준비와 SSE 전송만큼 늦다. 제품 HTTP·브라우저 경로는 재지 않았다.
- 1세션 10라운드다. 다른 날의 절대값과 비교하지 않는다.
