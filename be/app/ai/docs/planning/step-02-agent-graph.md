# 2단계 — LLM이 대화와 Tool을 선택하는 그래프

2026-10-24 · #167 · AI-PLAN-01·02·03. #166의 조건 변경 처리기를 연결한다. 내부 한 턴 실행이며 UI·공개 facade·DB 저장·검색은 이후 단계다.

## 예시부터 보기

현재 참가비 25,000원 → 사용자 “참가비 3만 원이면 어때?” → agent가 상담 답변 → Tool 호출 없이 종료, 값 유지.

이어서 사용자 “일단 그렇게 잡자” → agent가 앞선 대화의 3만 원을 참조 → Tool 호출 → tools가 검증해 잠정 반영 → agent가 실행 결과를 읽고 답변 → 참가비 30,000원과 새 대화를 호출자에게 반환.

사용자의 말을 정해진 의도 하나로 먼저 분류하지 않는다. LLM에 가능한 행동을 알려주고 실제 선택을 받는다. 선택과 결과는 Tool 호출 메시지로 확인하며 내부 사고 과정은 요구하지 않는다.

## 계약과 실행 흐름

- 입력: `PlanningAgentTurnInput(draft, current_message, history, reference_date, timezone)`.
- 출력: 답변, 최신 `draft`, 다음 턴에 전달할 `history`, 이번 Tool 실행 결과, 모델 호출 수, 반복 제한 도달 여부.
- `history`는 사용자·AI·Tool 메시지를 포함한다. Tool 요청과 결과를 함께 보존해 “왜?” 설명의 근거로 쓴다. 시스템 프롬프트는 호출자가 대화 이력으로 넣지 않는다.
- 실행 시 입력을 복사한다. 서버에 대화 세션을 보관하지 않고 호출자가 다음 턴에 history와 draft를 전달한다.

```text
START → agent ── Tool 호출 있음 → tools ──→ agent
          └──── 답변만 있음 ─────────────→ END
```

`agent`는 매번 최신 초안·기준일·이번 사용자 메시지 ID와 대화를 모델에 보여준다. 조건 변경 Tool의 JSON 스키마를 모델에 연결한다. 모델의 자연어를 새 조건으로 파싱하지 않는다.

`tools`는 호출 목록을 순서대로 처리한다. 허용 이름과 인자를 검사하고 `update_event_conditions()`를 실행한다. 잘못된 인자와 업무 검증 거절은 상태를 유지하고 이유를 `ToolMessage`로 반환한다. 알려지지 않은 Tool도 실행하지 않고 거절 결과를 반환한다. 예상하지 못한 코드 오류나 모델 API 실패는 정상 응답으로 감추지 않는다.

메시지는 LangGraph의 `add_messages` 규칙으로 누적하고, 초안은 검증한 새 객체로 교체한다. 이 단순한 순차 처리 때문에 첫 구현은 커스텀 tools Node를 사용한다. Tool마다 별도 Node를 만들지 않는다.

## 대화 지침

잠정 기준은 잠정으로 반영하고, 상담·가정 질문을 설정으로 오해하지 않는다. 짧은 수락은 직전 제안과 연결한다. 조건 질문은 대화에 도움이 될 때 한 주제 정도로 하고, 보류/이미 답한 주제를 곧바로 재질문하지 않는다. 설명 요청은 실제 상태와 실행 결과로 답한다. 출처가 없는 과거 행사 사실은 만들지 않는다.

최종 답변은 LLM이 생성한다. Tool이 적용되지 않았는데 적용됐다고 말하는지 여부는 실제 대화 검증 대상이다. 자유 문장의 모든 주장과 상태 일치를 코드로 완벽히 보장한다고 가정하지 않는다.

## 종료와 오류

초기 상한은 한 턴 Tool 실행 3회다. 초과 호출은 실행하지 않고 제한 결과를 반환하며, 마지막에는 Tool을 비활성화한 모델 호출로 완료·미처리 내용을 설명하게 한다. 이 상한은 측정 후 조정한다. 비활성화된 호출에서도 Tool이 나오거나 최종 답변이 비면 `AIInvalidResponseError`로 처리한다.

Tool 인자 오류는 수정 기회를 주지만 API 인증·연결 실패는 기존 AI 오류 분류를 따라 전달한다. 한 턴이 실패하면 호출자에게 성공 결과를 반환하지 않으므로 입력 초안은 그대로다. Tool 결과 메시지 없는 호출이나 잘못된 대화 이력은 모델에 보내기 전에 거절한다.

## 검증

API 없는 테스트: 대화만 하는 경로, 조건 변경 후 답변, 잘못된 인자 수정, 날짜 거절 설명, 여러 Tool의 순차 실행, 반복 상한, API 오류 전파, 입력 보존, 다음 턴 이력 전달.

실제 모델: 잠정 조건/보류 → 설명 질문, 상담 → 수락, 날짜 충돌 → 수정, 무료 → 미정 등의 작은 합성 대화. 상태와 Tool 선택은 자동 비교하고, 답변 자연스러움은 실제 문구를 검토한다. 모델·프롬프트·실행 코드·입력과 결과를 기록한다.

기술 근거: [공식 Quickstart](https://docs.langchain.com/oss/python/langgraph/quickstart)의 모델/Tool 순환과 [Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)의 메시지·상태 갱신 규칙. 설치된 langgraph 1.2.12에서 실행 검증한다.
