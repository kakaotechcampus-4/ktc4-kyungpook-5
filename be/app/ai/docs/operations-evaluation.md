# 운영 기능 측정 기록

운영 중(`ON_GOING`) 행사에서 쓰는 AI 기능의 품질과 시간을 같은 조건으로 다시 재고 비교하기 위한 기록이다.
최근 기록을 위에 쌓는다. 계약은 [contracts.md의 운영 Action 본문 초안](contracts.md#운영-action-본문-초안-333)을 따른다.

## 운영 Action 본문 초안 고정 사례 평가 (#333, AI-PLAN-09, 2026-11-06)

어떤 단계가 현재 단계가 되면 `draft_action_content`가 그 단계의 공지·발송 Action 본문을 쓴다. 이 평가는 그 본문이 입력에 없는 값을 지어내지 않는지, 운영진이 조금만 고쳐서 바로 올릴 수 있는 글인지, 초안 하나에 얼마나 걸리는지를 본다.

### 조건

| 항목 | 값 |
| --- | --- |
| 모델 | `gpt-5.6-luna` (`AI_MODEL`), 추론 깊이·온도는 지정하지 않음(공용 모델 기본값) |
| 프롬프트 | `action-draft-v1` (`features/operations/action_draft.py`의 `PROMPT_VERSION`) |
| 커밋 | 1회차 `7cdc89f`, 2회차 `818342d` (둘 사이에는 평가 판정 코드만 고침. 본문 작성 코드·프롬프트는 같음) |
| 문항 | [고정 사례 10개](../tests/fixtures/eval/action_draft_cases.json) = 단계 5개 × (값이 모두 있음 / 미정 있음). 사례마다 1번씩, 같은 10개를 2회 실행 |
| 미정 사례 | 장소·종료일·단계 기한·Action 기한이 비어 있음. 시작일은 운영 중이면 항상 있으므로 비우지 않음. 2개는 참가비도 비어 있음 |
| 실행 | 노트북에서 인터넷을 거쳐 게이트웨이 호출, 사례를 하나씩 차례로 호출 |

### 판정 기준

자동 판정(스크립트):

- **코드 검사:** 첫 호출에서 통과 / 다시 써서 통과 / 두 번 다 걸려 실패 / 모델 오류로 나눠 센다.
- **자리표시:** 공지(`NOTICE`)에서 장소가 없으면 `unknowns`에 "장소"가 든 항목이, 기한이 없으면(사전 안내 제외) "마감·기한·날짜"가 든 항목이 있어야 한다. 값이 모두 있는 사례와 발송 메시지(`EXTERNAL_SEND`)는 판정하지 않는다(`-`).
- **금지 표현:** "발송했", "확정됐", "예약했" 같은 완료 단정 표현이 없어야 한다.
- **제목 줄:** 공지의 첫 줄이 대괄호로 시작하지 않고, 행사명이 `unknowns`에 들어가지 않아야 한다.
- **이모지:** 2개 이하.

수동 확인(본문을 읽고 사례마다 적음):

- **통과:** 빈칸(`[ ]`)을 채우고 한두 단어만 고치면 바로 올릴 수 있다.
- **부분:** 필요한 줄이 빠져 운영진이 문장을 더 써야 한다.
- **실패:** 다시 써야 한다.
- 세부 장소·인원·시각·준비물을 지어냈는지도 이때 본다.

### 수동 확인에서 본 것

- **`survey_missing`은 두 번 다 부분이다.** 수요 조사인데 응답 기한 줄을 쓰지 않았다(1회차·2회차). 1회차는 장소 줄도 빼서 `[장소 미정]`이 없었다. 지어낸 값은 없다. 하지만 운영진이 "응답 기한" 줄을 직접 더 써야 한다. 2회차의 "단톡방에 의사를 남겨 주세요"는 응답 방법을 입력 없이 정한 문장이다. 공지를 올릴 곳이 단톡방이라 틀린 말은 아니지만, 비워 두는 편이 규칙에 맞는다.
- **사전 안내는 뼈대 수준이다.** `pre_event_full`은 일시·장소 뒤에 `[집결 시간]`, `[집결 장소]`, `[준비물]` 세 칸만 있다. 입력에 없는 값을 지어내지 않으라는 규칙을 지킨 결과다. 운영진이 세 칸을 채우면 바로 올릴 수 있어 통과로 봤다. 학술 발표회(`pre_event_missing`)에도 "집결 시간"을 써서 "시작 시간"으로 한 단어를 고쳐야 한다.
- **지어낸 세부 값은 없었다.** 20개 본문 모두 입력 장소를 늘리지 않았다(`가평 OO펜션` 같은 표현 없음). 예상 인원으로 "선착순 N명"을 쓰지 않았고, 시각·준비물도 쓰지 않았다. 본문에 쓴 괄호 요일 35개는 모두 날짜와 맞았다(코드 검사 통과). 요일은 코드가 계산해 입력에 넣어 준다.
- 금지 표현·대괄호 제목 줄·이모지 과다는 없었다.

### 남은 한계

- **다시 쓰기 경로는 실제 모델로 확인하지 못했다.** 20번 모두 첫 호출에서 통과해서, 검사에 걸린 뒤 어긴 값을 알려 주면 실제 모델이 고쳐 쓰는지는 미측정이다. 다시 쓰기는 가짜 모델 단위 테스트로만 확인했다(`tests/test_action_draft.py`).
- **사례가 적다.** 10개 × 2회라 검사 실패율이 0이라고 일반화할 수 없다. 반복 변동은 2회만 봤다.
- **요일을 넣지 않았을 때와 비교하지 않았다.** 요일을 코드가 넣어 준 효과는 미측정이다. 이슈 #333의 예시 자체가 2026-05-10(일요일)을 토요일로 적었을 만큼 요일은 틀리기 쉬워서, 처음부터 코드가 넣기로 했다.
- **코드 검사가 보지 않는 값이 있다.** 세부 장소·인원·준비물·응답 방법처럼 글자 형식으로 잡기 어려운 값은 프롬프트 규칙과 수동 확인에 기대고 있다. 이번 평가의 "단톡방에 남겨 주세요"처럼 그럴듯한 방법을 정해 쓰는 경우는 코드가 막지 못한다.
- **미정 기한 처리.** 수요 조사에서 기한이 없을 때 `[마감일]`을 넣지 않고 줄을 뺀 경우가 2번 모두 나왔다. 프롬프트를 고친다면 이 사례를 다시 잰다.
- **시간은 AI 호출만이다.** 운영진 화면에 초안이 보이기까지의 시간(BE 작업 시작·저장, FE 다시 조회 주기)은 #334·#335 연결 뒤 따로 잰다.
