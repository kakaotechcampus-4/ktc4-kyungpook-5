# AI 구조와 협업 기준

## 범위

AI 팀원이 기능별로 나누어 작업할 수 있도록 planning, retrieval, operations를 분리합니다. 현재는 폴더와 역할만 정의하며 구현·trace·evaluation은 포함하지 않습니다.

## Agent와 Tool

- Agent: 다음 행동을 스스로 계획·수정·평가하고 적절한 Tool과 Agent를 활용해 목적을 해결합니다.
- Main Agent: 전체 판단과 오케스트레이션을 담당합니다.
- Sub Agent: 위임받은 범위에서 어떤 Tool을 어떻게 사용할지 판단합니다. 독립적인 판단이 필요할 때 추가합니다.
- Tool: 정해진 입력과 수행 과정에 따라 실행합니다. 회계·계산은 Tool입니다.

기능 폴더나 그래프 노드 하나가 반드시 Agent 하나를 의미하지는 않습니다.

## 책임 경계

| 영역 | 책임 |
| --- | --- |
| AI | 조건 해석, 질문·계획·대응안 생성, 근거 구성 |
| BE | 행사 원본 상태, 금액·미납·환불 계산, 권한·승인 검증, 확정 변경과 실행 |
| workflow | 기능 연결·분기와 AI 실행 상태 관리 |
| tools | Agent가 사용할 도구의 입력·출력과 호출 처리 |
| facade / contracts | BE가 사용하는 공개 기능과 데이터 계약 |
| ports | AI가 사용하는 BE 기능 계약과 구현체 주입 |

LangGraph는 질문·수정·재계획의 분기와 반복을 연결하기 위해 사용합니다. 행사 변화는 BE에서 감지하여 필요한 AI 처리를 호출합니다.

행사의 업무 단계는 BE 데이터로 관리하며, 화면의 단계마다 그래프 노드를 만들지 않습니다. `state.py`는 AI 실행 상태 형식이고 `checkpoint.py`는 그 상태의 저장·복원 담당입니다. 행사 상태·채팅 기록·실행 체크포인트는 구분합니다. 저장 방식은 구현 시 BE와 합의합니다.

기록 검색은 실제 출처와 원문 위치를 반환하고 근거가 없으면 없다고 답합니다. 자료 준비·정제·색인이 필요해지면 retrieval 내부에 추가하고, 파일 저장·처리 상태를 포함한 BE와의 계약을 먼저 정합니다.

임베딩 모델은 게이트웨이가 제공하는 `text-embedding-3-small`이며 출력은 1536차원입니다. 저장소는 pgvector이고 청크 벡터 컬럼은 `vector(1536)`입니다. pgvector의 HNSW·IVFFlat 인덱스가 2000차원까지만 지원하므로 1536은 인덱스를 만들 수 있고, 3072차원 모델은 차원을 줄이지 않으면 인덱스를 만들 수 없습니다. 모델과 차원은 색인과 검색이 같아야 하므로 `llm.py`의 `EMBEDDING_DIMENSIONS`와 DB 컬럼을 함께 바꾸고, 바꾸면 저장된 벡터를 다시 만듭니다. 청킹 단위와 검색 방식, `sources[].location`의 내부 구조는 아직 정하지 않았습니다.

## 기능별 상세 범위

### planning — 계획 만들기와 수정

자연어 요청에서 행사 목표·인원·예산·일정 조건을 정리하고, 부족하거나 충돌하는 조건을 질문합니다. 제공된 기록 근거와 BE 계산 결과를 활용해 계획 대안, 단계·일정·담당 제안과 수정안을 만듭니다. 최초 계획뿐 아니라 운영 중 재계획에도 사용합니다. 계획의 확정·저장은 BE가 담당합니다.

### retrieval — 기록에서 근거 찾기

과거 행사 기록·장부·회칙에서 요청과 관련된 내용을 찾아 출처와 원문 위치를 구성합니다. 계획·운영 대응에 근거를 제공하고, 기록 챗봇의 질문에도 답합니다. 자료가 없거나 충돌하면 이를 명시합니다. 검색 결과를 곧바로 승인 정책이나 회계 확정값으로 적용하지 않습니다.

`tools/records.py`는 Agent에 노출되는 검색 도구의 입출력과 호출을 담당하고, 검색·근거 구성의 실제 기능은 retrieval에 둡니다. 같은 검색 로직을 두 곳에 중복 작성하지 않습니다.

### operations — 운영 중 변화에 대응

BE가 전달한 참가 취소·입금·견적·지출 등의 변화와 계산 결과를 바탕으로 현재 계획에 미치는 영향을 설명합니다. 추가 확인이 필요한 질문, 후속 작업, 대기자 충원·규모 조정 같은 대응안을 제시합니다. 변경 감지, 미납·환불 판정, 승인 검증, 메시지 발송·상태 변경 실행 자체는 BE와 Tool의 책임입니다.

### 함께 동작하는 예시

참가자가 취소되면 BE가 인원·예산을 재계산합니다. operations가 최소 인원 미달의 영향과 대응안을 정리하고, 필요한 경우 workflow가 retrieval로 과거 사례를 조회하거나 planning으로 수정 계획을 생성하도록 연결합니다. 승인 대상 변경의 검증과 최종 반영은 BE에서 수행합니다.

## 모듈 의존 경계

BE는 `app.ai`의 공개 이름만 import하며 AI 내부 구현에 직접 접근하지 않습니다.
AI는 BE 모델·DB·서비스를 직접 import하지 않고 주입된 port를 사용합니다.
공개 진입점은 `__init__.py`, 기능 구현은 `facade.py`, 공개 데이터는
`contracts.py`, BE 기능 계약은 `ports.py`에 둡니다. 업무 계약은 미확정입니다.

행사 원본 상태와 승인 레코드는 BE, AI 실행 체크포인트는 AI의 책임 범위입니다.
저장·트랜잭션·실행 방식은 별도 합의 대상입니다.
SSE·승인 interrupt·실행 재개는 이번 이전에서 구현하지 않습니다.
