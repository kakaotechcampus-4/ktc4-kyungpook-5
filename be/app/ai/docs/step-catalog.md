# 계획 단계 카탈로그

> 상태: 팀 검토용 초안. 단계 목록과 코드값은 합의 후 `app.core.enums`에 반영합니다.

## 범위

계획안(AI-PLAN-05)을 구성하는 Step과 Action의 기준 목록입니다. AI는 이 목록에서 행사에 필요한 단계를 고르고, 새 단계를 만들지 않습니다. 저장·승인·실행의 책임 경계는 [아키텍처](architecture.md)를 따릅니다.

## 기본 원칙

- Phase는 사전 준비, 모집·확정, 행사 진행·마무리 세 묶음으로 고정합니다.
- Step은 아래 목록으로 고정합니다. 이름·묶음·담당은 목록의 값을 그대로 씁니다.
- AI는 단계의 포함 여부, 묶음 안의 순서, 일정을 정합니다.
- 단계는 다른 묶음으로 옮기지 않습니다. 순서는 묶음 안에서만 바꿉니다.
- 앱은 메시지 발송·이체·결제를 직접 하지 않습니다. AI가 준비하고 운영진이 실행한 뒤 그 기록을 남깁니다.

## Action 유형

Action은 AI가 준비하고, 운영진이 실행하고, 실행 기록을 남기는 일입니다. 여섯 가지 밖의 일은 Action으로 만들지 않습니다.

| 유형 | AI가 준비 | 운영진이 실행 | 완료 기준 |
| --- | --- | --- | --- |
| `NOTICE` 공지 | 단톡방 공지 문구 | 복사해 직접 게시 | 게시 확인 기록 |
| `EXTERNAL_SEND` 개별 연락 | 미납자·업체에게 보낼 메시지 | 직접 발송 | 발송 확인 기록 |
| `CONTRACT` 계약 | 계약 조건 요약 (취소 조건 등) | 직접 계약 | 계약서 등록 |
| `TRANSFER` 이체·수금 | 받는 곳·금액 정리 | 직접 이체 | 이체 기록 |
| `EXPENSE` 지출 | 영수증별 지출 항목 | 확인 후 승인 | 장부 반영 |
| `CONFIRMATION` 확인 요청 | AI가 모르는 정보에 대한 질문 | 답변 | 답변 반영 |

앱은 게시·발송·이체 여부를 자동으로 확인하지 않습니다. 완료는 운영진이 남긴 기록으로 판단합니다.

## 단계 목록

담당은 Action으로 정합니다. 승인이 필요한 Action이 있으면 `APPROVAL_REQUIRED`, 없으면 `MANUAL`입니다. Action이 없는 단계는 운영진이 완료로 표시합니다.

### 사전 준비 (`PREPARATION`)

| 코드 | 단계 | 담당 | Action | 하는 일 |
| --- | --- | --- | --- | --- |
| `ASSIGN_ROLES` | 담당 인원 배치 | 직접 | `CONFIRMATION` | 분야별 담당자를 정하고 미배정 인원을 확인합니다 |
| `RESEARCH_VENUE` | 장소·교통 알아보기 | 직접 | `CONFIRMATION` | 장소·차량의 가능 여부와 견적을 문의합니다 |
| `DEMAND_SURVEY` | 사전 수요 조사 | 승인 | `NOTICE` | 수요조사 폼을 단톡방에 공지합니다 |

### 모집·확정 (`RECRUITING`)

| 코드 | 단계 | 담당 | Action | 하는 일 |
| --- | --- | --- | --- | --- |
| `RECRUIT_NOTICE` | 모집 공지 | 승인 | `NOTICE` | 참가 신청을 공지합니다 |
| `CHECK_RESPONSES` | 응답 확인 | 승인 | `NOTICE` | 마감 전 미응답 회원에게 안내합니다 |
| `CONFIRM_DETAILS` | 인원·일정 확정 | 직접 | — | 응답을 반영해 최종 인원과 날짜를 확정합니다 |
| `BOOK_VENUE` | 숙소·차량 예약 | 승인 | `CONTRACT`, `TRANSFER` | 확정 인원으로 계약하고 계약금을 이체합니다 |
| `COLLECT_FEES` | 참가비 수금 | 승인 | `NOTICE`, `EXTERNAL_SEND` | 납부를 안내하고 미납자에게 개별 연락합니다 |

### 행사 진행·마무리 (`EXECUTION`)

| 코드 | 단계 | 담당 | Action | 하는 일 |
| --- | --- | --- | --- | --- |
| `PRE_EVENT_NOTICE` | 사전 안내 | 승인 | `NOTICE` | 준비물·집결 장소를 공지합니다 |
| `EVENT_DAY` | 행사 당일 | 직접 | — | 출발 체크와 인원 확인을 합니다 |
| `SETTLE_EXPENSES` | 지출 정산 | 승인 | `EXPENSE` | 영수증을 정리하고 지출을 승인받습니다 |
| `REFUND_FEES` | 참가비 환급 | 승인 | `TRANSFER` | 불참·잔액에 따른 환급을 이체합니다 |

목록의 순서가 기본 진행 순서입니다.

## 목록에 두지 않는 일

- AI가 혼자 처리하는 일: 과거 기록 참고, 인원·예산 재계산처럼 운영진이 실행하거나 기록할 것이 없는 일입니다. 계획 대화와 운영 대응 안에서 처리합니다.
- 운영진이 추적할 기록이 없는 일: 발표 자료 준비, 리허설처럼 앱이 도울 Action이 없는 일입니다. 필요하면 목록에 추가하는 방식으로 다룹니다.

## 계획안에서 AI가 채우는 값

| 대상 | AI가 정함 | 목록 또는 BE가 정함 |
| --- | --- | --- |
| Step | 포함 여부, 묶음 안의 순서, `starts_at`·`deadline` | 코드, 이름, 묶음, 담당, ID |
| Action | 제목, 기한 | 유형, 승인 필요 여부, 상태, ID |
| 뺀 단계 | 빼는 이유 | 뺀 단계 목록 (목록 − 포함한 단계) |

계획 단계의 Action은 예정된 일입니다. 공지 문구·대상 인원 같은 초안은 운영 중 최신 상태로 만듭니다.

## 단계 삭제와 다시 추가

계획 중(`PLANNING`)에는 운영진이 단계를 빼거나 뺀 단계를 다시 넣을 수 있습니다. 목록이 고정되어 있어 뺀 단계는 목록에서 포함한 단계를 제외해 구합니다.

- 운영진이 뺀 단계는 계획안을 다시 만들 때 AI에 함께 전달합니다. 다시 만들어도 되살아나지 않습니다(AI-PLAN-07).
- 운영 중(`ON_GOING`)의 단계 삭제는 다루지 않습니다. 이미 실행한 Action이 있을 수 있습니다.

## 확인이 필요한 사항

| 항목 | 내용 |
| --- | --- |
| 보류 상태 | Figma v6에는 결정 보류가 있으나 `ActionStatus`에 보류 값이 없습니다 |
| 초안 문구 저장 | 승인한 문구와 버전을 담을 Action 필드가 없습니다. `payload`는 확인 요청 전용입니다 |
| `StepActor.AI` | 목록에서 쓰지 않습니다. enum 값은 재사용하지 않으므로 남겨 둡니다 |
| Step 코드 저장 | `steps`에 단계 코드 컬럼이 필요합니다. 초기 마이그레이션(#63) 전에 정하면 추가 리비전이 없습니다 |
