# 행사 조건 추출 평가

## 현재 검증 범위 (2026-10-22)

작업 2의 프롬프트는 `planning-conditions-v1`이다. be/.env 설정 후 gpt-5.6-luna로 합성 사례 18개를 실제 호출했다. 단위 테스트와 실제 모델 측정을 구분한다. 주입한 모델 응답을 사용하는 단위 테스트는 의미 해석 정확도의 근거가 아니다.

[사례별 결과 JSON](evaluation-results/planning-conditions-2026-10-22.json)에 실제 후보·적용 operation·미해결 근거·지연·fixture 및 핵심 코드 SHA-256을 남겼다. 커밋만으로 미커밋 구현을 재현할 수 없으므로 해시도 함께 기록했다. BE 저장·FE 표시 시간을 포함하지 않으며, 샘플이 18개라 nearest-rank p95는 최댓값과 같다.

관찰: 모호한 인원 변경은 기존 값 보존+NEEDS_CLARIFICATION, 날짜 역전은 코드에서 VALIDATION_FAILED와 원본 보존, 짧은 수락은 pending_offer 및 앞선 발화 근거에 연결됐다. 인용된 지시문 사례는 조건을 바꾸지 않았다. 전자는 모델과 코드가 결합한 최종 결과이며 모델의 원시 operation 정확도를 별도 측정한 점수는 아니다.

한계: 정답은 AI 작성 후 사람 검수 전이고, 작은 합성 세트를 한 번 실행했다. 이 18/18을 일반적인 정확도 100%, 안정적 p95 또는 주입 공격 방어 보장으로 해석하지 않는다. 반복 실행·실제 사용자 발화·필드별 오류율 평가는 남아 있다.

### 연결 과정에서 확인한 문제와 수정

1. 제한된 네트워크 환경에서는 18건 모두 AIRetryableError로 끝났다. 모델 품질 결과에서 제외하고 권한을 높여 연결을 재확인했다.
2. 실제 게이트웨이가 첫 요청에 HTTP 400 `invalid_json_schema`를 반환했다. Pydantic discriminated union이 생성한 `oneOf`를 허용하지 않는다는 응답이었다. 모델 추출 이전의 스키마 거부다.
3. field/op의 Literal과 엄격한 값 타입을 유지하면서 일반 Union으로 변경했다. JSON Schema는 `anyOf`를 사용한다. 프롬프트·평가 입력은 바꾸지 않았다. 자유 JSON이나 타입 검사 제거로 우회하지 않았다.
4. 수정 후 18개 요청이 모두 처리됐고 결과가 일치했다. oneOf/discriminator 재유입을 막는 회귀 테스트를 추가했다. 로컬 스키마 검증만으로 공급자 호환성을 보장할 수 없다는 점이 확인됐다.

관련 이슈의 원격 업데이트는 이번 작업에서 수행하지 않았다. 구현 PR/Issue 정리 시 이 문제·원인·결과를 함께 옮긴다.

`tests/test_planning_extraction.py`는 변경 적용의 원자성, 원본 보존, 이번 발화/문맥 근거, 단일 제안 수락, 중복·상충 변경, 잘못된 스키마와 모델 실패 전파를 검증한다. 스냅샷 형식 검증은 `test_planning_conditions.py`에 있다.

## 조건 추출 평가 재실행

`tests/fixtures/eval/planning_conditions.json`에 합성 사례 18개를 두었다. **AI가 작성한 초안이며 사람 검수 전**이다. 단위 변경, 명시적 해제, 무료, 부정·과거 인용·자기 정정, 다중 변경, 날짜 충돌·상대 날짜, 모호한 수락·명시적 제안 수락, 지시문 인용을 포함한다. 학습 데이터나 승인된 성능 기준으로 사용하지 않는다.

be/에서 설정한 뒤 실행한다:

```sh
uv run --frozen --group dev python -m app.ai.scripts.eval_planning_conditions
```

모델명·프롬프트 버전·커밋·미커밋 여부·샘플 수와 각 사례의 결과를 JSON으로 출력한다. 정확한 최종 조건/상태/미해결 필드 일치 수, 잘못된 필드와 지연을 확인한다. API 실패도 누락 없이 실패 사례로 남긴다. 승인 성능을 주장하기 전에 기대 정답을 사람이 검수하고, operation 수준의 누락·오탐/CLEAR 오류·모호함 확정 비율과 p50/p95를 포함하는 평가로 확장한다. 현재 작은 사례 집합은 초기 연결 확인용이다.

현재 스키마는 위 실제 호출에서 게이트웨이 수용을 확인했다. 공급자나 스키마를 바꿀 때도 로컬 검증과 실제 호환성 검증을 나누어 수행한다. 위 결과를 초기 기준값으로 남기고, 프롬프트/스키마 변경은 같은 사례로 비교한다.
